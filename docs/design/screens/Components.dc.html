Success message

Approved. The subcontractor has been emailed.

Shown above the record header after an action, with role="status". The text is always the code's own message, from ACTION_DONE in Review.gs.

The worklist could not load.The server did not answer. Nothing was changed. Try again in a moment; if it keeps failing, tell the owner of this tool.

Neutral, because red is reserved for At risk, Expired and fail. It says what failed, that nothing changed, and what to do next.

Record detail at narrow width · approved in the Batch C review · no new tokens

The rule uses a container query on the PDF-and-values row (.rd-split, container-type: inline-size), not a screen-width rule. It follows the component's own width, so it also works inside a frame. At 1440 the screen is pixel-identical to the approved version.

Component widthWhat changes 984 px and widerNothing. The PDF and values sit side by side and the PDF pane is sticky. Under 984 pxThe columns stack (440 + 24 + 520 no longer fit). The PDF pane stops being sticky, so it can't cover the values. That is a page of about 1048 wide. Under 576 pxEach value line becomes two rows: the label and result, then Found and Required side by side. The column header hides, and Found and Required get small caps labels (--text-xs, --tracking-caps, --c-ink-muted). In editing mode the label takes the full first row and the edit note drops to a third row. Edit inputs are 127 px at 375. That is a page of about 640 wide.

The "Below 85%: a person checks every value" pill also has a minimum height now instead of a fixed one (24 px, 3 px vertical padding, --lh-sm), so it grows to two lines on a phone. It is unchanged on one line. Live examples are in Batch C, frames 4p and 4q.
